IMPLEMENTATION
maxima/desktoplinks/com/eurobuddha/maxima/desktoplinks/MinimaDocsLink.java:
shared loopback-only service, explicit one-use two-minute connection codes, hashed
256-bit scoped credentials, immediate revocation, fixed minimaDocs invitation
channel, strict fields/Host/Origin/size limits, request deadlines, bounded inbox,
replay tombstones and idempotent request journal. PrivateFiles.java extracts the
existing AccountFiles atomic owner-only write implementation; AccountFiles reuses it.

DesktopNode hooks both built-in MaximaNode and classic DesktopJarEngine into the
same service. SettingsPanel adds Connected apps approval and revocation controls.
ParlonsCore owns the included account service and routes invitations before chat.
ParlonsLocal exposes approval controls only behind its existing owner session and
local-device authorization. The owner panel and scoped companion port stay separate.
account/src/main/resources/panel/app.js adds the controls to existing Settings.

MaximaNode admits validated passive invitations through its retained-message gate.
Classic SocketTransport queues a mailbox barrier on the manager lane. Main retains
failed invitation notifications for retry; it withholds mailbox acknowledgement
until application persistence succeeds. DesktopJarEngine propagates invitation disk
failures, including when its sink is not ready. Existing chat behavior is preserved.

Desktop runtime includes jdk.httpserver; account and desktop compile the same
shared service without adding HTTP dependencies to Android. Version sources align
with app metadata and filenames. Node fatJar now has an explicit release version.

minimaDocs retains its existing encrypted main-process client, account-separated
People/share/inbox UI, direct QR flow and Pairing permission checks. MacBackend's
existing invitation exposes its wire line; document transfer is still the original
minimaDocs protocol. No new third-party dependencies were introduced.
