Minimum adaptations
Retain the existing Maxima network, contact book, document protocol and invitation
application string. Android broadcasts cannot run on macOS. Add one shared Java
desktop connection service, compiled into the standalone and included account
hosts. Adapt their existing lifecycle and message callbacks to that service.
Use ChatPort for contacts and sending; use the existing reliable sender when
available. Do not route app invitations through the chat application channel.
Add a main-process client and UI to minimaDocs. No new third-party dependency.
Extend existing host settings/panel with Connect minimaDocs and Revoke controls.
Update minimaCore's bundled node artifact and digest together after host tests.

User flow
1. minimaDocs People > Connect Parlons explains the two supported hosts.
2. In the chosen host, Connected apps > Connect minimaDocs displays the account,
   contacts/invitation permissions, and a short-lived connection link.
3. Paste that link into minimaDocs. Review the host and connect. A connection
   link is distinct from a document invitation; neither auto-accepts the other.
4. People shows separately labelled account sections, search, refresh, add and
   remove contact, and received document invitations. With two hosts, both appear.
5. Share > Parlons contacts > account > recipient > Can view/Can edit > Send.
   Create the existing document invitation only after the user confirms Send.
6. Recipient reviews the invitation through the existing Pairing preview/accept.
   Accepting establishes the existing minimaDocs document connection. Dismissal
   removes the inbox entry while preserving replay protection.
7. Disconnect in minimaDocs revokes the host credential. If the host is offline,
   report that revocation failed and offer a separate explicit Forget on this Mac
   action; never imply local deletion revoked the host.
8. Revocation in the host rejects subsequent requests immediately. An offline host
   shows a retry state without mixing another account's contacts or clearing data.

UI
Reuse the approved Atelier palette, Manrope typography, dialogs and text controls.
No stock icons. Preserve direct QR/link/recipient controls. Label contacts by host

Show queued, sent-to-relay and received states accurately. A queued invitation is

Local protocol v1 (new shared host service)
Listen on 127.0.0.1 only. Persist a per-profile port or provide rediscovery on
restart; keep the same advertised account id. Host and Origin checks follow
ParlonsLocal; reject browser Origin headers on companion API routes. No CORS.
All endpoints are POST /minimadocs/v1/<operation>, Content-Type application/json.
Except connect, require Authorization: Bearer <256-bit random token>.
Never put bearer tokens in URLs, renderer IPC, logs or public discovery files.
API body limit 32 KiB; response limit 256 KiB; requests time out at 20 seconds.

Connection link:
minimadocs://parlons/v1?port=<1..65535>&provider=<desktop|core>&account=<64 lowercase hex>&code=<64 lowercase hex>
account is the SHA-256 fingerprint of the host account public key, not a filesystem
path. code expires after two minutes and is single-use. Only a host approval action
mints it. Provider and account must match the redemption response. Distinct host
profiles maintain distinct credentials. Codes and pending registrations are bounded.

Every successful response includes ok:true, provider, account. Errors have ok:false
and a safe error string. Non-2xx HTTP status is an error; never follow redirects.

connect {code} -> {token, name, publicKey, ...envelope}
contacts {} -> {contacts:[{key,name,address}], ...envelope}
invitations {} -> {invitations:[{id,from,line}], ...envelope}
invite {to,line,requestId} -> {state:"queued"|"sent", ...envelope}
contact/add {address} -> {state:"introduced", ...envelope}
contact/remove {key} -> {removed:boolean, ...envelope}
dismiss {id} -> {...envelope}
disconnect {} -> {...envelope}

Token scope is fixed to the existing minimaDocs invitation application and contact
operations. No arbitrary command/application parameter, wallet, seed, media, chat
history, arbitrary URL or generic RPC forwarding. Every request rechecks approval.
Requests must not claim another identity or silently fall back to a different host.
invite requestId is retained with its outcome so a retry cannot duplicate delivery.

Persistence and message handling
minimaDocs encrypts credentials with a key derived from its existing workspace key
and writes atomically with mode 0600. The renderer receives only connection ids,
names, provider labels and validated contact/invitation records. On restart it
restores the selected connections without gaining access to host owner sessions.
The host persists approvals and bounded received invitations within the account's
private storage. Retain at most 64 invitations for seven days and bounded replay
tombstones. Durably store before acknowledging Maxima mailbox delivery. Disk errors
must propagate into the existing delivery retry path instead of silently dropping.
Validate application, authenticated sender, payload size and invitation shape;
full key and permission validation still happens in minimaDocs Pairing before accept.
Poll while the People/share view is active; allow explicit Refresh. No overlapping
polls, silent resend or unbounded retries. Late responses cannot replace a new view.
