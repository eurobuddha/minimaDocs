# minimaDocs for Mac

The first Mac version is **0.1.0**, for **Apple Silicon and macOS 13 or newer**.
It uses the approved minimaDocs workspace, Manrope, and the same offline editors
and encrypted Maxima document protocol as Android.

## Use it

Open `minimaDocs-0.1.0-mac-arm64.dmg` and drag minimaDocs into Applications.
Java and the editor engines are bundled; no separate runtime or Office account
is needed. Create a document, spreadsheet or layered image from Files, or choose
Import. Each editor opens in its own window.

- Word and Excel files remain editable DOCX/XLSX files. Export also offers PDF;
  images support editable `.minimadocs-image.json` projects and flattened PNG.
- **Command-S** saves, **Command-O** imports, **Command-N** creates a document,
  and **Command-Shift-H** returns to Files. Autosave checks every 30 seconds
  after two seconds without edits. Closing or quitting asks about unsaved work.
- **Share** creates a QR/link invitation or shares with a previously paired
  recipient. **People** has your own QR code. **Open invitation** accepts pasted
  invitations and QR image files. New recipients exchange keys using an invitation
  before a bare Maxima address can be used.
- **Share → Access & updates** shows who has access, allows the owner or an
  administrator to change/remove permitted roles, and shows queued updates.
- Saved snapshots travel through the app's embedded lightweight Maxima node.
  Keep minimaDocs open for delivery. Concurrent remote versions remain separate;
  choose one to review, then use Save a copy to edit independently.

The Mac workspace lives in `~/Library/Application Support/minimaDocs`. Its
database, files and identity keys are encrypted; macOS Keychain protects the
workspace key. Export important documents before moving to another Mac. Copying
the workspace directory alone is not a supported migration procedure.

### First-version limits

- Apple Silicon only; an Intel installer has not been built or tested.
- Parlons Desktop does not expose Android's linked-app contacts interface yet.
  Direct minimaDocs QR/link/recipient sharing is available; a live Parlons contact
  book is not integrated in this Mac version.
- Sharing sends saved document snapshots, rather than simultaneous cursor/typing
  sessions. The file limit is 16 MiB. Delivery requires reachable Maxima relays.
- Invitations expire after 15 minutes. Unlike Android, this initial Mac UI does
  not yet ask for owner approval when somebody accepts an expired invitation;
  create a fresh invitation instead.
- No camera QR scanner, notebook import/migration, automatic app updates or Mac
  store publication is included in this initial build.

## Build

Use an Apple Silicon Mac with Node/npm, a JDK with `jlink` and `jmods`, and
ImageMagick (`magick`). Prepare the pinned offline editors using the repository's
[Android build instructions](../README.md#build-android); Mac packages those exact
generated assets. It does not download an editor at runtime.

From the repository root:

```sh
cd android
./gradlew -p ../desktop/backend test packageInput
cd ../desktop
npm ci
npm run prepare:mac
npm test
npm run test:ui
npm start
```

`JPACKAGE_JDK` can select the JDK used to create the bundled runtime. Set the
Gradle Java home separately if the system Java version is incompatible with
Gradle. Development was verified with the bundled runtime built from JDK 26.0.1.

The Office compatibility UI test also needs `android/build/fixtures/compatibility.docx`
and `compatibility.xlsx`, generated by
`node scripts/create-office-fixtures.cjs /path/to/office-engine` from the repository
root after preparing the editors. This helper also requires Python 3.

### Signed installer

The Mac packaging and notarization scripts reuse PandaGet Desktop's Developer ID
workflow. With the developer certificate installed and Apple credentials stored
in the `minimadesk` Keychain profile:

```sh
npm run dist:mac:signed
```

This signs and notarizes the app and DMG, staples their tickets, then checks the
Developer ID signature, hardened runtime and Gatekeeper assessment. The result
is `dist/minimaDocs-0.1.0-mac-arm64.dmg`. The version source is `package.json`;
the backend jar reads that same version. Signing credentials are not in the repo.

## Architecture and verification

- Electron's main process owns native dialogs, window lifecycle and Keychain access.
  Sandboxed renderer windows have scoped bridges and bundled HTTPS asset routes.
  Workspace and editor origins are separate; document renderers cannot call the
  workspace's pairing and sharing operations.
- A bundled Java backend communicates over framed private stdin/stdout pipes.
  There is no local HTTP bridge. It reuses Android `DocumentStore`, `RichDocument`,
  `NoteStore`, `Pairing`, `Post` and `Node`, with the existing Windows SQLite and
  file adapters. Mac Keychain protection replaces Windows DPAPI.
- Backend tests include the portable Android suite plus Mac encryption, failed
  saves, stale sessions, concurrent versions and duplicate-editor checks.
- Electron UI tests exercise real editors, DOCX save/reopen, save-on-quit, duplicate
  opens, DOCX tables/header/footer preservation, XLSX formulas/results/frozen panes/
  filters, layered image projects, PDF and PNG export.
- `./gradlew -p ../desktop/backend transportProbe` from `android/` exercises two
  live Maxima nodes exchanging authenticated encrypted messages in both directions.
  That probe is not a complete Mac-to-Android attachment delivery test.

Development UI tests use isolated fixture directories and an offline synthetic
key. Packaged builds ignore that test environment switch and always use Keychain.

After packaging, `node --test tests/packaged-ui.test.cjs` opens the real signed app
and checks Keychain storage and all three bundled editors. This opt-in test uses
the normal Mac workspace and opens disposable unsaved drafts. It never saves or
shares a document. Quit an existing minimaDocs instance before running it.
