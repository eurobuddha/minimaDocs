# The Android app

Native Android views and local SQLite; no WebView, no AndroidX, no XML layouts. The pad is its own Maxima node — the transport's core is vendored under `maxima-core/` and runs inside the app — so nothing else has to be installed for sharing to work, and nothing at all for the pad to work. [../docs/SHARING.md](../docs/SHARING.md) is the sharing design, [../docs/MAXIMA-TRANSPORT.md](../docs/MAXIMA-TRANSPORT.md) is how the node is carried and looked after, and what has actually been seen on a phone is in a verification log the maintainer keeps privately, build by build.

**This page is the design record of the interface, and the log is the record of what is true now.** Most of what follows was written as each piece was built and still describes it. Where it and the verification log disagree, the log is right. Four things below are history rather than description, and are marked where they stand: the Minima Core connector, the *Syncing settings* box (its job is done by **⋮ → Profile** and **People and devices**), the shelves one level at a time and the *cards or a list* switch (Home replaced them in 0.2.002), and the list of what was cut from the pad — search and favourites came back, as the search bar and the dock.

It opens where you left it: on Home, or on the ruled note you were writing, with the cursor in it. Home is laid out like a phone's own home screen — notes and collections as icons, a **+** at the foot, the search bar and a dock of favourites under them — and a collection holds notes, other collections and files, as deep as you like ([docs/HOME.md](../docs/HOME.md) is the whole design). Anything can be shared from its own menu or its mark.

The line under the open note's title says where it stands in marks, not words: its sync mark, then a round
for each person it reaches, tinted by where they stand; while it is being saved or sent, a few words beside
them say so and go. Tap the mark or a round for the rest.

## Build from source

Requirements: JDK 17, Android SDK platform 36 / build tools 35.0.0, Gradle 8.11.1 (wrapper), Android Gradle Plugin 8.10.1. Point `ANDROID_HOME` to the SDK, or put `sdk.dir=/your/sdk` in an untracked `local.properties`.

```sh
cd android
./gradlew testReleaseUnitTest lintRelease assembleRelease
```

Windows: `gradlew.bat testReleaseUnitTest lintRelease assembleRelease`.

The release APK is **unsigned**, under `app/build/outputs/apk/release/`, unless `android/keystore.properties` names a key — see `app/build.gradle`. No signing key is required to compile. To test locally, run `assembleDebug` or `installDebug` for an APK signed by your own development key. Android refuses to install a build over one signed with a different key, and uninstalling takes the notebook with it: export a backup first.

App ID `org.mininotes.android`, version in `app/build.gradle`, Android 9+. This initial ID must be finalized before public distribution. Retain the same signing identity for upgrades.

## Implemented and limitations

Every element on screen has to earn its place against a paper pad, which has none. What survived:

- **It opens where you left it.** Home comes back as Home, with the collection that was open over it; a note being written comes back as that note; with nothing remembered, the last note written in. The app remembering something different from where you were is the app deciding it knows better.
- **The ruled note.** A note opens ruled to the bottom, cursor at the end of the text. The keyboard stays down until you ask for it: a note you open is a note you are reading, and a keyboard covering half of it is in the way. A tap or a double tap on the page says you mean to write and brings it up; **holding a word to select and copy it does not**, because a keyboard sliding over the thing you are selecting is the opposite of helping. A blank note is the exception — there is nothing to read on one, so it opens ready to write. Writing takes no decision: no title to fill in, no formatting, no save button. Text autosaves half a second after typing stops and on leaving the screen. The rules are drawn from the text's own line height, so they fit the writing at any size rather than being a fixed pattern behind it.
- **One menu, wherever you open it.** Every `⋮`, and the menu a held icon brings up, says the same things in the same order: the reading ladder, the colours of the thing and their tone, its icon, then *Undo* when there is something to undo, then what can be done to that thing (its versions or a file for it, move, share, sync, favourite, archive, delete), then what can be done with its text (send to another app), then the app itself, under small headings — *Find* (Search, Tree view), *Put away* (the archive, the bin), *People*, *Backup*, and *Mininotes* (Send files, Sent files, Settings, Profile, Feedback, Share Mininotes, About). A menu that changes shape from screen to screen has to be read each time; this one is learnt once. Only what cannot apply is missing: Home has no name or icon of its own, and the archive and the bin are places rather than things, so they carry only their own one line.
- **Send to another app takes whatever you are standing in** — one note, the notes in a collection, or from Home's `⋮` the whole pad — as one piece of text with a blank line between notes, in the order you put them in. The note being written on is taken from the screen, so what leaves includes the words typed a moment ago.
- **Every collection and note can be given a colour of its own**, from the dots in its `⋮`: eight and none. Its icon and its card are washed with it, and an open note is written on paper of that colour — enough to recognise it across a grid, not enough to fight the writing. What is stored is *which* colour, never a pixel value, so a thing keeps its colour when the paper under it changes; each colour has a strength for the light paper and one for the dark. Nothing inherits: a collection's colour is the collection's, and its notes stay as they are unless you say otherwise.
- **And an icon of its own, or a picture.** `⋮` → **Icon…**, right after the colours, or a tap on the face before a note's title or a card's name, opens one box: the colours along the top, a search, *Default* first — the note glyph, or for a collection the mini-grid of what is inside it — then the 1,857 icons of the Lucide set, and **Choose a picture…** at the end. A tap on an icon is the choice, and the box closes. A picture is cut square from the middle, turned the way the camera held it, and made small enough to travel, 32 KB at most, with the strip at the foot saying so; `⋮` → **Remove the picture** puts the icon under it back. Icon and picture go with the thing to whoever it is shared with. A thing this phone only reads keeps the look it came with, and its menu has no *Icon…*.
- **⋮ on the note** opens with the reading ladder, and under it the colours this note can be given.
- **The reading ladder: A−**, ten rungs, **A+**, and it sets the size of everything the app draws — the writing, the names under the icons, the menu itself — because a name is as hard to read as a note when the text is too small. Each piece of text keeps its own proportion to the note's size and is scaled from it, live, without the screen being rebuilt under the finger. Each tap steps one rung and the writing behind the menu changes as you go, so the size is found by looking at the note rather than by naming it; the rules open out and close up with the text, because they are drawn from its line height. The rungs fill to where you are, the end you have reached greys out, and the size is remembered.
- **The paper is a whole set rather than a tint** — the ink, the rules, the cards, the menu and the accent are chosen for it, so the pad reads the same way light or dark. Which one is in use comes from the phone, not from a control in here. **Send to another app** goes through the Android share sheet — the share sheet already offers the clipboard, so there is no second row for it. Sending to another app is plain text leaving Mininotes through an app you choose, and is nothing to do with sharing over Minima.

**One control, one meaning.** Every screen reads the same way:

An icon carries its face, its name, its mark and, for a favourite, a star; nothing else is on it. To move, share, archive or delete a thing, hold it for its menu, or open it and use its own `⋮`. Sharing is one row in that menu, and the mark on the thing opens the same box, so there is one place to look for anything — the thing itself.

Home has no back control: nothing is above it. The phone's own back closes a menu first, then the overview, then a card one level at a time; on Home with none of them, it leaves the app. From a note it goes back to where the note was opened.

- **Home is a phone's desktop.** Under the bar — Mininotes and which build this is, the mark for everything on this phone, and `⋮` — Home's notes and collections are laid out the way a phone lays out its apps: icons, four across on a phone held upright (three on a narrow screen, more on a wide one), in the order you give them, and after them the files other devices sent, each with *new* on it until it is opened. A note's icon is the note glyph on the paper it is written on, and a collection's the mini-grid of what is inside it, unless either wears an icon or a picture of its own. The name sits under it, in two lines at most, with the mark on one corner and a star on the other for a favourite. At the foot on the right is a round **+**; under the grid, the search bar; under that, the dock.
- **Hold something and what can be done to it comes up beside it**; keep moving and you have picked it up instead. Both come out of the same press, told apart by whether the finger stayed still — which is why the menu is drawn in the app's own window rather than a popup one, so the finger that opened it still belongs to the icon underneath.
- **Let go on another thing, and a thing goes with it.** A note let go on a note makes a new collection holding both, named *Untitled* with the name ready to be typed over, since a gesture cannot say what it is called. Anything let go on a collection goes into it, and a file let go on a note becomes that note's attachment. Let go in an empty cell, it stays in that cell, and a quiet outline shows where it will land: icons stay where you put them, gaps and all, as on a phone's own home screen, and nothing moves up to fill a gap (since 0.2.005, the owner's ask). Out of a card onto the dimmed Home round it, it comes up a level. On the dock it is a favourite, at the place it is let go. If any of it would change who receives it, that is said by name and confirmed first, exactly as moving is.
- **A collection opens as a card over Home**, the way a folder opens on a phone's desktop: its name at the top with its face before it, its mark and its `⋮`; its icons; and its own **+**, while Home's is hidden. A collection inside it opens in the same card, with `‹` and the name of the one it is in to go back up — phones do not nest folders, and a stack of cards would hide the grid they belong to. The phone's back goes up a level and then closes the card; a tap on the dimmed Home closes it at once. Files dragged onto it from another app are kept with that collection.
- **The dock holds five favourites**, faces only, as a phone's dock has no words; each says its name to whoever uses a screen reader. More than five, and the rest are in a *Favourites* icon, first on Home, which cannot be moved, renamed or deleted. `⋮` → **☆ Favourite** puts a thing in the dock while there is room, and **Remove from the dock** takes it out and leaves it a favourite. Empty, the dock says *Favourites*, quietly.
- **What is open is one swipe away.** A short handle above the dock says it can be swiped up: swipe up from the dock, or tap the handle, and the notes and collections you have open stand side by side as cards, the newest first, as a phone shows its open apps. Tap one to go to it; throw it up, or hold it, to close it; **Close all** is the one button. Up to twelve are kept, and they are still there after a restart.
- **The search bar finds anything**: notes, collections and files, by name and by what they say, from the second letter typed. Before anything is typed it shows your favourites and what you wrote in lately. **⋮ → Tree view** is everything at once, every collection and note, indented by how deep it sits.
- **+ is the one way to make something.** It sits at the foot on the right of Home and of every card, and offers *Note* and *Collection*, made where it is: a note opens at once, to be written on; a collection is made as *Untitled*, and its card opens with the name ready to be typed over. The open note carries no **+**, because a note is for writing on. A note nobody writes on is never stored, and an existing note emptied to nothing is removed, so the pad does not fill with blank sheets.
- **The archive and the bin are on Home, as a phone keeps its bin on its desktop** (since 0.2.006, the owner's ask). Each is an icon with how many things wait in it; a tap opens a card of what is in it, and a note or a collection let go on one is archived, or goes in the bin, as its menu would do it - said, with **Undo** in the next menu. They can be moved to any empty cell, as every icon can, but are never renamed, shared or put away. Settings → **Show the archive and the bin on Home** switched off puts them back in `⋮` → **Open the archive** / **Open the bin**, the lists they were.
- **A thing says where it stands with its mark**, on its icon's corner, at the top of its card, and on the line under a note's title, where a round for each person it reaches follows it. It is one of six, the same as the PC's: only here, waiting to go, sent and not yet confirmed, everybody has it, paused, not heard from; Settings → *What the marks mean* says each. Tapped, a waiting mark says what is waiting and for whom, with **Send now**; any other opens who has it. What other people share with you is not kept apart in a box of its own: it stands among your own things, on Home and in the collections it came out of, and says on itself where it came from.
- **Nothing leaves in one tap, and nothing leaves by surprise.** A note or a collection is either where you put it, put away in the archive, or waiting in the bin. `⋮` → **Archive** puts it away; `⋮` → **Delete** drops it in the bin. Either way it is still there and still holds whatever it held — an archived collection keeps what is in it, and it travels with it — so neither asks anything.
- **A thing in the archive or the bin is not a place you can walk into**, so tapping it offers where it can go instead: **Put back**, and then **Move to the bin** or **Delete for good**. Putting something back brings back whatever holds it too, since a note put back into a binned collection would be back nowhere.
- **Only what cannot be undone asks.** **Delete for good** names the thing and says what is in it — *This cannot be undone. Anything inside it goes too* — and the bin's own `⋮` holds **Empty the bin**, which says how many things that is before it does it. Deleting for good takes the sharing rules that pointed at it with it.
- **A place is not a thing.** The archive and the bin have the same menu as everywhere else, and it is short: the two ladders, then **Empty the bin** in the bin and nothing of its own in the archive, then the app's own items. Neither can be renamed, coloured, moved, shared, sent, copied out or sent to another app — a bin is not something to share, and what is waiting in one is not something to send on. Put a thing back first and it is a thing again, with the whole menu.
- **Files that come from another device land on Home**, marked *new* until they are opened, and are then files like any other: hold one for *Open*, *Save a copy*, *Send to a device*, *Put in a note*, *Move to…* and, under a line, *Delete*; carry it onto a note or into a collection. Somebody who is not one of your own devices is asked about first — *Accept* or *Refuse* — in a box, or a notification that opens Home. **⋮ → Send files** sends files straight to a paired device, in no note, and **⋮ → Sent files** lists what went and where each stands, with what is still coming above it. *(History: until 0.2.002 they were in a Drop box, a tile of its own.)*
- **`⋮` → Profile is this phone as others see it.** *Your name*, what other people see, and *This device*, what your own devices call it, each changed where it stands; its code and address, with **Copy address**; one line under *Connection* — connected, or the one thing to do about not being — with how many notes are waiting to go; and **Export** and **Import**. *(This was a box of its own called Syncing settings, which began with "Core installed" and "Mininotes enabled in Core", and later four ticked lines about the node. None of it is a step any more: nothing else has to be installed.)*
- **Nobody copies an address by hand.** The node knows its own, and the code on the Profile page carries it.
- **It goes on listening after it is closed**, once there is a device to hear from, and Android shows a notification for as long as it does. *Listen while the pad is closed* in Settings switches it off, and so does **Stop listening** on the notification. A note that arrives then is said in one line — who, and what kind of thing, never what it says — and tapping it opens that note.
- **A note written in from the other end while you have it open changes on the page**, where it stands, with anything you had typed since the last save kept. The page used to go on holding the older text, and the next word typed wrote it back over what had arrived.
- **Sharing is one box**, the same from a thing's mark and from `⋮` → **Sharing**: under *Who has access*, each person with a round initial and their role — Owner, Admin, Can write, Can read — which the owner or an admin changes from a drop-down, and **Add someone**; under *Syncing*, *Sync automatically* and how long it waits, *Sync now*, *Pause receiving*, and **Unfollow** for anyone but the owner, which tells the others. It is decided per share, so the same person can have one collection of yours to read and another to work in, and a rule on a collection covers everything inside it, however deep, including what is added later. [The sharing design](../docs/SHARING.md) has the rules. *(History: until v0.0.101 it was a list of every address, each tapped along from not shared to reads to reads and writes, with *I share this with* above it and *My address* below.)*
- **No address is ever typed.** Nobody types sixty characters of Maxima address correctly. Another device is added by scanning its code: the phone's own camera opens the `mininotes://` link a code carries, and in the app **⋮ → People and devices → Share with someone** opens the scanner, with pasting offered on it for a line that was sent; a whole pairing line goes to pairing, a bare address is simply saved. This device's own code and address are in Profile, and behind **Add a device** in People and devices.
- **Whose a device is, is a switch.** In **People and devices**, *My devices* are listed first, this one at the top, then *People*; the *My device* switch on a device moves it between the two — both ways with a device of yours, one way to anybody else — and holding one offers to forget it. A device that arrives is saved as somebody else's, which is the careful way round; the code that offers the whole pad (*Connect my other device*) is the one that makes it yours at both ends. *(History: this was the addresses line of the Syncing settings box, each address with `● mine` or `○ mine`, and devices were added from **+ → From another device**.)*
- **Nothing is renamed from a menu.** A note's title is tapped where it stands, in the note's bar; a collection's name is tapped at the top of its card; either turns into the field it already looks like, and tapping away keeps what is in it. A collection made by **+**, or by letting a note go on a note, opens with its name ready to be typed over, because a gesture cannot say what the new thing is called.
- **`⋮` → About is what this is, where it came from, and where to send something.** The version goes up with every build that leaves here, so a screen can be matched to the thing that drew it; under it the source, and under that an address to donate to. Both lines are drawn whether or not there is anything to put in them yet, saying plainly that it is coming rather than quietly not existing.
- **A newer build is said, and brought here on a tap; Android does the installing.** Once a day at most, when the pad is opened or come back to, one line of text is read from the repository (`dist/latest.txt`) and compared, number by number, with what is installed. Nothing is sent with it and nothing is downloaded. If the published build is later, the pad says so in one line the first time it hears of it, and **Update to v…** stays in the `⋮` menu and in About for as long as that is true. No box is put over the page. Failing is silent and tried again at the next opening. About carries the switch that stops the daily look, under which **Check for a newer version** still looks when tapped. *(Until v0.0.107 it looked only when asked, which meant somebody who never opened About never learned that a fault had been fixed.)* Tapping the row opens a box whose one button is **Update** *(since v0.0.109; until then it opened the release page and the person did the rest)*: the pad fetches the build from the repository's release - the file the workflow named after the tag, and the checksum beside it - saying how far it has got in the strip at the foot of the window; checks that the file matches the checksum, is this app, is a later build, and is signed with the key this build was signed with; and hands it to Android's installer, which asks before installing, and the first time asks whether this app may install at all. A build signed with another key - a development build against the published one - is refused in words before Android has to, with the release page offered instead. When the new build opens it says *Updated to v…* once. What was fetched is cleared away at the next opening whatever happened.
- **Every box keeps the same room around what it says.** Words touching the edge of the thing they are written in read as if they were cut off, so a hand's width at the sides and air above and below, whether the box holds a line, a list, or a note from last Tuesday.
- **The way out is drawn largest.** The back arrow is the control most often reached for, so it is bigger than the marks beside it.
- **Home says whose it is.** `Mininotes`, with which build this is under it, sits quietly in the middle of Home's bar: the bar is built to one measure — a place on the left for the arrow, the name in the middle, the mark and `⋮` on the right — and on Home, where there is nothing above, the arrow's place is kept empty rather than closed up, so the name never moves. The note screen stays bare: its bar is the arrow, the note's face and title, and `⋮`, with one quiet line under the title kept for a save that failed or a note that is read only.
- **The keyboard is one more edge of the screen.** Newer Android no longer shrinks a window for it, so the app keeps clear of it itself: whichever is deeper, the navigation bar or the keyboard, is left free at the bottom. The page is written down to that edge and no further, and a menu opened over it keeps to the room that is left, scrolling inside it rather than hiding its last items behind the keys.
- **Two devices tell each other who they are.** The code in Profile, and behind **Add a device** in People and devices, shows this device's line — where to send and the two keys, one to seal for it and one to check what it signs — as a code to point a camera at and as text to copy. Scan or paste the other device's line; once paired, each shows six digits for the other under People and devices ("Check with them"), taken from the keys themselves: if a pasted line was changed on its way, the digits will not agree, and the device should be forgotten. The line is not a secret — anybody who has it can write to you and nobody who has it can read what you send — so the digits are what trust rests on.
- **The camera is only ever a way to read a code.** It opens while the scanner is showing, is looked at frame by frame for a code, and closes the moment one is found. Nothing is recorded and no frame is kept. It takes either kind of code: one that is a whole pairing line goes to pairing, and one that is only an address is saved as an address.
- **This device's own keys** are made on first use and kept in the app's own storage, sealed under a key the phone's Keystore holds. A device may be paired with before it knows its own Minima address — the keys are what pairing is for, and where to send arrives with Core.
- **Every note keeps its history.** `⋮` → **Versions** on a note lists what it has said — when each was kept, and whether it was written here or came from an address — any of them can be read whole, and **Put this back** writes it as a new version rather than erasing what happened in between. A version is kept when an editing session ends rather than at every keystroke, so the list is a history and not a keystroke log; a hundred are kept per note, which for text is nothing.
- **Two people writing at once lose nothing.** Revisions are counted rather than timed, because two phones whose clocks disagree cannot be sorted by time without somebody's writing disappearing. What arrives is weighed against what this phone has and against the text both sides last agreed on: if it descends from what is here it is taken, if this phone has already written past it it is ignored, and if both sides wrote, the two are merged line by line. Changes in different places both land, silently. Where both wrote over the same lines, nothing is chosen for you and nothing is put away: the note keeps what each of them wrote, and whoever reads it deletes the line they do not want.
- **A note can keep a file.** The 📎 at the foot of the note you are writing opens the system picker, and what you pick is kept with the note: counted in one quiet line beside the clip, which opens into a card for each, tap one to open it in whatever app handles it. The 🎤 beside it records straight into the note. A picture pasted on the page - a screenshot copied, a picture the keyboard sends - is kept with the note the same way, as a messaging app takes one (Android 12 and later, since 0.2.007); words pasted stay words. A file is **copied** into the pad's own folder rather than pointed at — what another app lends you can be moved, renamed or withdrawn, and a note that loses what it held because something else tidied up is not keeping anything. 25 MB a file, and the pad says so when it is holding 500 MB altogether.
- **So can a collection, and Home.** `⋮` → **Add a file…** on a collection, or files dragged onto its card from another app, are kept with that collection and shown among its icons; files dragged onto Home from another app are kept on Home.
- **Files follow their note.** Archiving takes them along, deleting for good deletes them, and emptying the bin gets the room back. Bytes nobody has a row for are swept up: the row is written after the copy and deleted before it, so the one thing that can be left behind is a file nobody claims — never a name you can tap and never open.
- **Importing asks which you meant.** **Add to this pad** brings the backup's notes in beside your own as copies, reusing the collections that are already here and making the ones that are not, so nothing lands nowhere. **Replace everything** is a restore: the pad becomes what the backup was, ids included, so the sharing rules that pointed at those things still point at them. Replacing says how much it is about to delete and cannot be undone, and it happens in one transaction — a restore that failed half way would be worse than the one it replaced.
- **A backup carries the collections as well as what is in them** — every collection at every depth, the files kept with them and on Home, and every note's and collection's icon and picture, not only notes — because a backup of notes alone restores onto a phone with nowhere to put them. A backup from 0.1, with its collections and books, still reads.
- **A backup is a zip**, because a backup that restores the writing but not what it held is not a backup of the note: `mininotes-backup.json` and beside it the files. Import reads either kind — a backup written before files existed is that text on its own and still restores. An import adds copies, so a copied note's files are copies too, under ids of their own; importing a backup into the pad it came from leaves the originals exactly where they were. A zip is unpacked into a room of its own first, and only a plain id is taken from an entry name, so a zip cannot name a path to write to.
- **Sharing carries the writing, and the files.** A file kept with a shared note, or since 0.2.004 with a shared collection, goes with it, up to 16 MB: it is handed to the transport's own media service, sealed and cut into pieces, rather than put in a message. See *What a file kept with a note does* in [the sharing design](../docs/SHARING.md).
- **A web address in a note is an address.** Addresses are marked when the typing stops — underlined, in the accent colour — and tapping one opens it. Tapping anywhere else only moves the cursor, so nothing opens by accident.
- *(History: until 0.2.002, `⋮` → **Show as a list** laid a level out one thing under another instead of across the screen, and **Show as cards** put it back. Home and every card are icon grids now, and **⋮ → Tree view** is the list of everything.)*
- **One size for everything that is read.** The writing, the name under an icon, and every line of the menu are the same size, because they are all words you read rather than furniture — a name you cannot read is no better than writing you cannot read. The app's name in the bar is one of them — it is a word you read, so it is that size too. What is not words stays small and out of the way: the counts under a name, and the marks for where a thing stands and what is owed.
- **It opens at the ordinary size.** The middle rung is 17 point — what everything else on the phone writes in — so the app looks like the rest of the phone before anyone touches anything. Sizes are drawn in `sp`, so the phone's own text setting still moves them all; the ladder is a way to leave the ordinary size, not a thing you have to set before you can use the app. Ten rungs, 11 to 29, opening on the fifth: five either way, the steps growing as they go up because a size you can already read needs a bigger push to be noticeably bigger. Home keeps its columns whatever the size — four across on a phone held upright — and the names under the icons grow with it, in two lines at most; the menu widens with its words until there is no more screen to give it.
- **What is kept is the rung, not the size.** A ladder can be re-cut; a rung means the same thing afterwards, so a pad kept in the middle stays in the middle. A size written by an older ladder is not read at all — that pad opens at the ordinary size, which is the one place worth starting from.
- **A coloured thing wears its colour at the edge.** A wash has to stay light enough to be written on, and eight light washes look like eight shades of the paper; the edge is the colour itself at full strength, so two things are told apart at a glance rather than by comparing tints.
- **Boxes are written on the app's own paper.** Every dialog takes the background, ink, accent and corner of the pad it interrupts, light or dark, and a line to write on is a box with a rule round it rather than the platform's underline — at the size everything else is read at. A box that asks for a name says what closing it does, because closing is what keeps it.
- **A colour, and how loudly it lands.** The reading ladder, then the nine colours of the thing you are standing in, then the tone. The colours are eight plain ones — red, orange, yellow, green, teal, blue, purple, pink — as far apart from each other as eight can be, so two things are never told apart by a shade. The tone says how much of that colour reaches the paper, pastel at one end and the colour itself at the other, drawn as the wash each one would actually make. Two questions, because one answer cannot be both. Everything is pointed at rather than stepped to, and the page behind the menu repaints as you go.
- **The tone belongs to the whole pad**, like the reading size: it is a matter of taste rather than of which note this is. The colour belongs to the thing.
- **Home can be coloured too.** A collection's colour comes from its own menu; Home's `⋮` colours the whole pad, which belongs to no collection and so is kept beside the other things the app remembers about itself.
- **A card shows the colour of the collection it is.** You cannot see a collection's own icon from inside it, so its card takes the wash — colour a collection from its card's `⋮` and the card changes under the menu.
- **Light or dark is the phone's setting, not ours.** The app is written on a light paper when the phone is light and a dark one when it is dark, and follows the moment that changes — the way every other app decides it. The ten-paper scale of greys is gone: it was a choice nobody wants to make twice, and it sat in front of the one choice that is actually about this pad. The other papers remain in the source as what those two are cut from.
- **A note's title is a word of its own.** It sits in the note's bar, after its face, drawn bold; tap it to change it, and the page underneath is all writing. It used to be the note's first line, which tied two things together that are not one thing — the first thing somebody writes is often not what the note is called. A note with no title is known by its first line, on its icon, in the overview and in a backup, and one with neither by *Untitled*.
- **Press and hold anything to carry it where you want it.** The icon lifts, the others part to show where it would land, and letting go there is the order, kept and written silently. Held against the top or bottom of a long grid, it scrolls. Let go where nothing takes it and nothing moved. Home and every collection have an order of their own. Holding still opens the menu; moving while holding carries — onto a collection, out of a card, onto the dock, or onto a note, as above — and what a move into somewhere else would change is checked first.
- **A grid keeps the order you gave it.** Until something is dragged, a grid reads newest first, and anything new — a note, a collection — arrives first, which is where you are looking for it. Once you have dragged, that order is what stands: writing on an old note no longer pulls it back up, because the order is yours now.
- **Move somewhere else**, in a thing's menu, turns the screen into the places it can go, and you tap one; where it is already is shown greyed as "where it is now". A collection goes onto Home or into any collection that is not inside it.
- **A move that changes who can read something has to be confirmed.** Before anything is written the app works out the audience the note would gain and lose, and says so by name: *Moving "Ideas for the allotment" into Reading changes who receives it. Starts reaching: Ana (someone else).* A move that changes nobody just happens.
- **Nothing is confirmed and nothing is cancelled.** A box closes by tapping outside it, and closing is what saves it: type a name and close, and the thing is named; close without typing and nothing happens. The only buttons left are ones that *do* something — Delete, Move anyway, Put them together, Send now, Close all — never OK, Cancel, Done or Close.
- **A single warning line** under the note's title, only when a save fails; tapping it retries. On a note this phone only reads, it says *Read only*. Whether the note has reached everybody is the mark's to say, on the line below. Silence means saved.
- **The amber `↑` marks anything somebody has not been given yet**: on the note, and on every collection holding it, with a count in a bar of how many notes inside are waiting. A note counts once however many devices are owed it, because the mark says *this is behind*, not how many deliveries that is. Write one more word on a note that had reached everybody and the mark comes back, which is the whole point of it. Where all that waits is for a device still on 0.1, its box says *"Ana's phone needs to update Mininotes to receive this"*, with nothing to press: it goes once that device is updated.
- **`⋮` → Sync now** says what that thing owes and to whom, by name, and sends it. Most of the time nobody needs it: what the open note owes goes by itself once the writing has stopped for as long as that thing asks for, and everything owed goes when the pad opens. **Only an answer clears a mark**: the other device saying it has the note, never a relay taking the message. See *A phone that answers* in [the sharing design](../docs/SHARING.md).
- **The menu is drawn by the app, not taken from the platform**, so that the reading ladder can live in it: a platform menu row can only be tapped once and dismissed, and stepping a size means staying open and watching the note. It is the same sheet in both bars — rows of words, thin lines between the groups — so the two menus stay one thing.
- **Backup**, under its own heading in every `⋮` — *Export backup* and *Add from backup* — and in Profile. It exists because app storage is the only copy and uninstalling deletes it. *(Syncing settings, which stood beside it, is Profile, People and devices and Settings now.)*

Removed as unjustified for a pad: the separate notebook field, the trash view, and every screen heading and tagline. The title field was on that list, and came back as a word of the note's own, in its bar. Pins and the search box were on it too and came back once there was enough to lose things in — as favourites and the dock, and the search bar over it, which opens on *Favourites* and *Recent* before anything is typed, with **⋮ → Tree view** beside it. `notebook` and `deleted` remain in the database and the backup format so existing backups still load.

Collections are the exception to that pruning, and sharing is their justification: you share what you organise, so there have to be things to organise into. Writing is unaffected — the app opens where you left it, and a first run opens on a blank page, already in a collection, so nothing must be chosen before writing.
- **Three workers, each serialized.** The notebook's, so that a read always observes the writes queued before it and a result for a screen the reader has left is dropped instead of drawn. One for whatever waits on the network and somebody is waiting for — sending, pairing, asking the node for its address. And one for the housekeeping a node wants when it has just come up, which nobody is waiting for. They were one worker for a long time: a word typed waited to be saved behind a note being sent, and leaving the app stalled for two seconds waiting on a relay.
- A note row reads a 280-character preview rather than the whole note; the whole note is read only when it is opened. The store refuses to write a partially read row back over a stored note, so a preview can never truncate the original.
- The schema is versioned with ordered, additive migration steps — version 31 since 0.2.002, and `SchemaMigrations` is the list: each step says what it added and why, and each has a test. A step is never edited after it has shipped. A failed step leaves the previous schema and notes intact, and a database written by a newer build is refused rather than rewritten.
- JSON import/export through Android's document picker, compatible with the initial MiniDapp format. Import is transactional and creates new IDs. No migration silently moves browser data.
- *(History.)* `CoreConnection` is a source-built connector to a separately installed Minima Core: explicit package target, random pairing and request ids, response token checks, bounds and timeouts, and only registration and the read-only `status` command. It was built when Core was expected to carry the post. Core's build turned out to have no Maxima in it, the pad became its own node instead, and nothing in sharing touches this any more.
- The sealed-note format for sharing: ephemeral P-256 ECDH, HKDF-SHA256, AES-256-GCM and an ECDSA signature, so a relaying node carries a note it cannot read or alter undetected. It proves a message is intact, not who sent it; matching the sender's fingerprint to a paired device is the caller's job. See [the sharing design](../docs/SHARING.md).
- Unit tests for everything that can be decided without a device, each in a class with no Android types in it: causal revision ordering, the merge, what to do with an arriving note and with the page that is open when it arrives, who is a member of what and which of two decisions stands, what travels in a parcel, what each address is still owed, the sealed-note format, the pairing line and the short form of a key, QR drawing and reading, SHA3, schema version rules, the workers' ordering, failure, flush and shutdown, search, where a dragged icon lands and what letting it go does (`Grid`), the tree of collections and what fits a 0.1 device (`Things`), what is open (`Overview`), the icon set, a picture's size (`Thumb`) and which face a thing shows (`Looks`), how a colour is laid over a surface, attachments, and the feedback form.

Notes are stored **unencrypted** in the app's private SQLite database until the notebook is locked: **⋮ → Settings → Lock Mininotes** encrypts the notebook, its files and its backups (SQLCipher), and it then opens with the fingerprint or screen lock, with a backup password and twelve recovery words as spare keys. What is shared is sealed end to end either way. Saving is asynchronous: `onPause` and `onSaveInstanceState` wait up to two seconds for queued writes to reach disk, so a process killed during a slower write can still lose the last edit. A save that fails while the note is open is shown and can be retried; one that fails after the note was closed reopens it with the text so it can be retried, unless a different note was opened first, in which case the app says the edit was not stored rather than replacing what is on screen.

What has been exercised, on which phone and on which build — including, every time, what was *not* seen — is written down before each release in a log the maintainer keeps privately, because it names their phones and quotes their notes. Nothing should be believed about a device on the strength of the code alone; ask in an issue for the log's entry for a build.

## The Minima Core connector (history)

The adapter is an original implementation of the public upstream contract; no binary AAR is bundled. Its identifier strings are based on the Apache-2.0 upstream source pinned in `../docs/research/core-upstream-commit.txt`. The upstream token protocol authenticates the peer holding the pairing token; it is not Android certificate pinning. Initial registration trusts the installed application at the explicit Core package. Nothing that arrives through it is allowed to edit the notebook, and nothing in sharing goes through it: notes arrive through the pad's own node, sealed, from a device whose signing key was paired with, and from nobody else.

This app never requests Admin or grants permissions in Core. Pairing tokens, addresses, keys and note content must not enter logs or OS cloud/device-transfer backup — the log lines the node and the post write are counts and outcomes only. Explicit note backups remain available through the document picker.
